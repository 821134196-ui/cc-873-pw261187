# 配置中心发布器（Config Center Publisher）

三个应用（`order-service` / `payment-service` / `inventory-service`）共享部分配置键，
各自有覆盖值、依赖关系与版本约束。本项目提供一个发布器，支持：

1. **影响范围计算**：一次改动的直接命中 + 沿反向依赖边传播的完整影响闭包；
2. **发布拦截**：检测到循环引用或版本不相容（含缺失依赖）时阻止发布；
3. **批量回滚 + 精准刷新**：一批发布整体回滚，只向原先受影响的客户端推送刷新；
4. **操作页**：查看键的来源（全局层 / 应用覆盖），分 4 步逐步确认更新。

零第三方运行时依赖，仅使用 Python 3.11 标准库；测试使用 pytest。

## 目录结构

```
config_center/
  semver.py      # SemVer 与版本约束（>=, <=, ^, ~, 逗号 AND）
  store.py       # 三层模型存储：全局层 / 应用覆盖 / 应用约束，JSON 持久化
  publisher.py   # 影响分析、环检测、相容性校验、原子发布、批量回滚
  notify.py      # 按应用订阅的 SSE 通知中枢（精准投递）
  server.py      # ThreadingHTTPServer：REST + SSE
  seed.py        # 三应用演示数据
  static/        # 操作页（原生 HTML/CSS/JS，无构建）
tests/           # 32 个 pytest 用例
scripts/demo.py  # 不依赖 HTTP 的端到端演示
```

## 快速开始

```bash
python3 -m config_center --reseed --port 8000
# 浏览器打开 http://127.0.0.1:8000/
```

命令行演示与测试：

```bash
python3 -I scripts/demo.py
python3 -m pytest tests/ -q
```

## 模型说明

### 三层取值

| 层级 | 含义 |
| --- | --- |
| 全局共享层 | 键的默认版本，保留全部历史 revision；应用未覆盖时穿透取值 |
| 应用覆盖层 | 应用对某键钉住自己的版本/值/依赖（如大促独立扩连接池） |
| 应用约束 | 应用声明消费哪些键及可接受版本范围，如 `^1.0.0`、`~1.4.0`、`>=1.0.0, <2.0.0` |

依赖关系挂在**具体 revision** 上，因此覆盖一个键也可以替换它在该应用视角下的出边。

### 影响分析（`POST /api/prepare`，dry-run）

1. 在内存副本上预演全部改动，不写真实数据；
2. 直接命中：应用对该键的生效版本会变化（全局改动对已有覆盖的应用不可见）；
3. 反向依赖闭包：从命中键出发沿「谁依赖我」的边传播，得到完整受影响键集合；
4. 在**模拟后的未来图**上跑 DFS 三色标记环检测；
5. 对闭包内每个键按应用约束做 SemVer 相容性校验；
6. 同时校验 `depends_on` 指向的键真实存在。

任一检查失败则 `ok=false`，`/api/release` 返回 422 并保持原数据不变（原子性）。

### 批量回滚（`POST /api/rollback`）

- 每次发布的事件里保存受影响 `(app, key)` 的**发布前快照**（含来源层级）；
- 回滚取这批发布之前每个键的最早快照，在临时存储上预演反向操作；
- 回滚本身同样要通过环检测与相容性校验，不安全则阻止；
- 被回滚发布引入的全局 revision 会被清理，使最高版本真正回到发布前；
- 刷新目标取各发布 `affected_apps` 的**去重并集**——未受影响的客户端不会收到任何 SSE 推送。

### 通知（SSE）

`GET /api/subscribe?app=<name>` 建立 SSE 连接；发布/回滚后中枢只向事件
`affected_apps` 中的在线客户端投递 `refresh` 事件。操作页右侧的「模拟客户端」
面板可直接观察到这一行为。

## REST 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 全量状态 + 每个应用的生效视图/依赖图/在线客户端数 |
| GET | `/api/key-sources?app=` | 每个键的来源层级、生效版本、全局历史与覆盖详情 |
| POST | `/api/prepare` | dry-run 影响分析（不写入） |
| POST | `/api/release` | 校验通过才原子发布，并推送精准刷新 |
| POST | `/api/rollback` | 按发布事件 ID 批量回滚，只刷新原受影响客户端 |
| GET | `/api/events` | 发布/回滚事件历史 |
| GET | `/api/subscribe?app=` | SSE 订阅 |

## 操作页向导

发起改动 → ① 编辑改动（可批量加入清单）→ ② 影响分析（直接命中、传播闭包、
环/不相容/缺失依赖报告）→ ③ 确认发布（仅校验通过可进入）→ ④ 结果与实际刷新的客户端。
点击任意键名可打开「键来源」抽屉，对照全局历史版本与应用覆盖。
